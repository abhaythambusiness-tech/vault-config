# 00 - Flujo de Software

> [!resumen] En cristiano
> Flujo estándar de 6 documentos para el desarrollo de software, desde la definición inicial hasta el cierre y archive. Se adapta a cualquier tipo de proyecto (micro SaaS, SaaS, startup o proyecto a medida).

## Los 6 documentos obligatorios

| Documento | Propósito | Cuándo crear |
|---|---|---|
| `1 - PRD` | Product Requirements Document: qué hacer y por qué | Al inicio del proyecto |
| `2 - TRD` | Technical Requirements Document: cómo se implementa técnicamente | Después del PRD |
| `3 - UI-UX Design` | Diseño de interfaz y experiencia de usuario | Después del TRD |
| `4 - AppFlow` | Flujo de API y integraciones (backend) | Junto con el UI-UX Design |
| `5 - Backend Schema` | Estructura de datos y modelo de base de datos | Después del AppFlow |
| `6 - Plan de Implementación` | Cronograma, hitos y responsable de cada fase | Después del Backend Schema |

## Flujo recomendado

1. **Definir el PRD**: objetivos, público objetivo, funcionalidades clave.
2. **Especificar el TRD**: decisiones tecnológicas, pil stack, dependencias.
3. **Diseñar la UI-UX**: flujos de usuario, wireframes, diseño visual.
4. **Definir el AppFlow**: endpoints, autenticación, integraciones externas.
5. **Esquematizar el Backend**: modelo de datos, relaciones, migraciones.
6. **Planificar la implementación**: cronograma, hitos, revisiones periódicas.

## Reutilización

Este flujo es intemporal y sirve para cualquier proyecto de software, independientemente del nicho o tecnología utilizada. Los documentos se pueden adapting replacing el contenido específico, pero la estructura de 6 documentos se mantiene.
